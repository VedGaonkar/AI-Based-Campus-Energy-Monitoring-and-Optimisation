# Optional internal sustainability reporting

This is an optional commercial reporting module for one authorised building, not a certified ESG rating, campus ranking, carbon credit calculation or billing/payment integration. It is disabled by default. An Administrator enables it at **Sustainability / ESG > Module settings**. Existing accounts, memberships, source data, control policies and approved palette remain unchanged. There is no automatic building comparison.

## Environmental methodology v1

Select one configured import meter, one data mode and non-overlapping current/baseline UTC periods (each at most 366 days). Equal elapsed durations are required for a percentage. Current and baseline share the same accepted-reading derivation as the energy engine: meter/epoch/register/data-mode separation, non-overlapping representations, and interval-energy preference. Only `kWh`, `import_kwh`, finite nonnegative accepted readings are eligible. Rejected/review readings do not contribute. Cumulative deltas retain their source IDs; no reset is bridged across epochs. Boundary intervals are excluded in full, never prorated.

Electricity is the sum of eligible whole intervals. No readings means **unavailable**, not measured zero. Long intervals (over the existing engine's 1.05-hour gap threshold) contribute their known aggregate kWh but not regular sampling coverage. This conservative threshold follows the current hourly energy engine; daily billing aggregates are not hourly coverage. Regular coverage is regular-interval hours / requested elapsed hours x 100. Data gaps are listed and are not filled. Accepted is an input-validation state, not independently verified meter accuracy. Recorded source types, mode, excluded-reading counts and gaps accompany the output. A mixed/submeter total is never invented. Reporting is bounded at 20,000 stored readings per selected meter/mode before the latest requested endpoint, including predecessors; exceeding the bound fails explicitly rather than exporting a partial feed. Archival aggregation is a future extension.

Estimated electricity-related **kg CO2 = accepted interval kWh x applicable kg CO2/kWh**. No CO2e claim is made. A factor must apply to the entire interval. Newer append-only factor revisions take priority where their effective dates match. If a new factor boundary crosses an interval, that interval's emissions are unavailable rather than prorated or assigned an older factor. Missing factor coverage yields an unavailable period emissions total and separately labelled partial known emissions. Energy gaps mean any emissions estimate covers recorded electricity only, not the unobserved full building period.

Without a configured factor the explicit default is **0.675 kg CO2/kWh, user-specified assumption**, with geography/year unspecified. Enabling persists that assumption as revision zero, once; a GET never writes or approves it. Every saved report captures this assumption's stable version and metadata. Once an explicit factor is recorded, only explicit versions apply; dates outside them have missing factor coverage rather than silently falling back to the broad assumption. Custom factors always retain assumption status; clients cannot submit an official verification flag.

Official-source check on 2026-11-14: [CEA official database directory](https://cea.nic.in/cdm-co2-baseline-view?lang=en&mappingId=234) links [User Guide v22.0, August 2026](https://cea.nic.in/api/cdm-report-version/view-pdf/en/82). Table S (printed page 1 / PDF page 6) gives the FY 2025-26 unified Indian grid net-generation-weighted average **0.675 tCO2/MWh**, including renewables/captive injection and cross-border adjustments. Unit conversion yields **0.675 kg CO2/kWh**. This differs from operating/build/combined margins intended for project displacement calculations. Appendix C/annexures describe year-specific grid factors. The module provides an explicit Administrator opt-in for this source/year/geography only, effective 2025-04-01 through 2026-04-01 UTC. It does not automatically apply that historical factor to other years, isolated grids, supplier contracts or formal reporting programmes. The source is authoritative for the cited statistic; suitability for the institution's reporting methodology still needs review. This is a generation-based consumption estimate, not a transmission-loss-adjusted or market-based inventory. The original user assumption is not silently promoted merely because its number matches this official statistic.

Observed reduction (%) = (baseline recorded kWh - current recorded kWh) / baseline recorded kWh x 100. Negative values are increases. Missing/zero baselines or unequal elapsed durations produce no percentage. Incomplete periods retain clearly labelled partial recorded totals and a provisional comparison warning. This is not a schedule-normalised or weather-normalised comparison, nor the anomaly engine's timestamp baseline. Confirmed timetable room-hours are compared; at least 20% difference is flagged, and no comparable timetable evidence is unknown. Occupancy is explicitly unknown/similar/different; a declared comparison needs a written evidence reference. No participation or occupancy is inferred from electricity.

Monetary estimates use the snapshotted configured Settings tariff in INR/kWh, where finite/nonnegative. They show recorded-use cost and baseline-minus-current cost difference, including negative differences. Exclude taxes, fixed charges and tariff history; do not present verified software savings. Current settings have an installation default tariff; this is labelled configured, not utility-verified.

Recognition requires the disclosed configurable reduction threshold (default 5%, allowed 0.1-100), regular coverage in both periods (default 90%, allowed 80-100), closed equal periods, positive baseline, live mode and no calculation/source/context warnings. Comparable timetable and documented similar occupancy are required. Wording is factual: recorded use decreased compared with the selected baseline. It does not assign causation to the software.

## Social evidence

Administrators record campaign/activity name/date, students/staff counts, energy-saving initiative, responsible staff and evidence reference. Counts may be attendance or deduplicated within the activity. New records are pending; an Administrator records an approval/rejection note. Review history is retained. This is internal review, not independent verification. Evidence references may be controlled document identifiers; no file upload/public sharing is introduced.

Internal engagement score = sum(student + staff counts) / sum(eligible participation opportunities) x 100, using only approved evidenced activities in the selected current period that declare deduplication within activity and a positive denominator. Counts cannot exceed the declared denominator. Attendance and unknown denominators are displayed but excluded from the score. Different activities may include the same people: the denominator is participation opportunities, not unique campus members. Zero recorded opportunities means unavailable. Recognition of approved activities is separate from energy recognition; lower electricity never supplies a social input.

## Governance evidence

Policy and reporting records require covered period, responsible staff and evidence; review date is optional and explicit. A report record can reference an energy review/reporting-consistency document. The documentation index has four visible equal criteria (25 points each): approved evidence of a policy covering the full selected period; that policy reviewed within the period; an approved reporting record covering the full period; and regular energy coverage meeting the configured minimum in a closed period. All evidence IDs and recorded inputs accompany the rubric. This index measures recorded documentation only. Missing evidence says **not recorded**, never that no policy exists. Saved report creation alone does not auto-approve a governance achievement.

## Permissions and exports

All routes use existing authentication, membership, CSRF/Origin and immutable institution database binding. Read-only module settings and enabled previews/approved evidence are available to building members, like existing building electricity analytics. Pending/rejected evidence, settings writes, factor versions, evidence creation/review, saved-report list/creation and JSON export require Administrator. No client institution ID/role is accepted. Identifiers from another building produce no access. New journal invalidations reuse existing live synchronisation and reconnect repair; HTTP remains authoritative.

An Administrator saves/exports the selected periods through the same backend calculator used for preview. Save recalculates the latest accepted data for those filters; the returned snapshot is authoritative if a reading arrived since preview. A later saved-report export never recalculates. The existing `Report` model stores module marker, full methodology/version, periods/context, interval and source-reading input snapshots, factor versions/metadata, configured thresholds/tariff/timezone, source quality/gaps, approved evidence/review status, scores/rubric and a SHA-256 checksum of the serialized snapshot. This checksum detects accidental changes; it is not a signature or external certification. Factor revisions and report snapshots have no edit/delete API. Evidence may be re-reviewed; older reports preserve the previous status. Report exports and writes are audited. JSON is a machine-readable full-evidence export; PDF/CSV formatting and payment integration are outside this implementation.

## Persistence

Additive per-institution collections: `sustainabilityConfig`, `emissionFactors`, `sustainabilityRecords`; existing `reports` stores immutable API snapshots. Enabling uses singleton ID `module`. Atomic factor revision allocation and a unique revision index define deterministic history even with concurrent factor creation. Failed writes may leave revision gaps; history is never renumbered. No data reseed, account migration or existing-record mutation is required. Real-world occupancy assertions, evidence authenticity, meter calibration and applicability of reporting standards require institutional review.
